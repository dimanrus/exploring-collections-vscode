## 🚀 Быстрый старт

1. Установите расширение из Marketplace (или нажмите `F5` в клоне этого репозитория).
2. Запустите отладку на **любом** поддерживаемом языке и остановитесь на точке останова.
3. В панели **Variables** щёлкните коллекцию **правой кнопкой** → **🔍 Explore collection**.
4. Либо вызовите команду **`Exploring Collections: Explore a Collection…`** из палитры команд и выберите любую переменную текущего кадра.

| Как открыть | Где |
| --- | --- |
| `🔍 Explore collection` **CodeLens** | **Над каждой коллекцией, доступной на точке останова** — по одной кликабельной ссылке на коллекцию, прямо в остановленном файле |
| `🔍 Explore collection` **ссылка в подсказке** | Наведите курсор на переменную-коллекцию в остановленном файле и щёлкните ссылку во всплывающей подсказке |
| `🔍 Explore collection` **контекстное меню** | Правая кнопка на переменной в **Variables**, **Watch** или **Call Stack** (`locals`) |
| `⌨️ Ctrl+Alt+E` / `⌘+Alt+E` | На любой поддерживаемой переменной во время отладки |
| `⌨️ Ctrl+Alt+Shift+E` | Выбор переменной из палитры команд с поиском |
| `🧭 Activity bar → Exploring Collections` | Каждая сессия отладки раскрывается в **список своих коллекций** (имя, количество элементов, тип); ниже — закреплённые и недавние снимки |
| `💡 Подсказка в строке` | На остановленной строке: `🔍 temperatures (14) · explore with Ctrl+Alt+E` |
| `🧪 Просмотр данных` | CodeLens над литералом коллекции в редакторе — **без запуска отладки** |

```text
    var temperatures = new List<Temperature>();     ▸ 🔍 Explore collection · temperatures · 14
    var lookup = new Dictionary<string, int>();     ▸ 🔍 Explore collection · lookup · 3
    Console.WriteLine(temperatures.Count);          ← остановились здесь
```

CodeLens появляются сразу при остановке, обновляются на каждом шаге и при смене кадра, и исчезают с завершением сессии. Каждая ссылка стоит на строке, где коллекция *появилась*, поэтому несколько коллекций из одного выражения не собираются в одну строку. Если идентификатора в этом файле нет (поле, параметр, сгенерированный член), ссылка привязывается к строке объемлющего объявления вместо точки останова, а команда **Show Diagnostics** показывает точную строку и причину выбора для каждой ссылки. Отключается настройкой `exploringCollections.showCodeLens`.

### 🧪 Без точки останова

Данные, **прописанные прямо в коде**, можно открыть без отладки. Поставьте курсор в файл с литералом коллекции и вызовите из палитры команд `Exploring Collections: Preview Collection Data from Source` — или просто нажмите CodeLens `🧪 Просмотр данных` над самим литералом:

```python
temperatures = [                                  # 🧪 Просмотр данных · temperatures · 3
    {"city": "Seoul", "degrees": 21},
    {"city": "Busan", "degrees": 24},
    {"city": "Incheon", "degrees": 22},
]
```

Разбор понимает синтаксис литералов поддерживаемых языков: массивы и объекты JavaScript/TypeScript, C# `new List<T> { new T { … } }` и `new Dictionary<K,V> { ["k"] = v }`, списки записей F# и JSON-документы. После правки литерала нажмите `Ctrl+Alt+R`, чтобы перечитать данные.

## 🌍 Поддерживаемые языки

Четыре языка, две стратегии захвата: **.NET читается только через встроенный помощник** (один запрос к отладчику на всю страницу), а **JavaScript/TypeScript читается из preview адаптера**, с откатом на универсальный обход переменных, если адаптер preview не отдаёт.

| Язык | Адаптеры | Быстрый путь | Нативный помощник |
| --- | --- | --- | --- |
| **C#** | `coreclr`, `clr`, `vsdbg`, `dotnet` | файл помощника (1 запрос) | ✅ обязателен — `ExploringCollections.Helper.dll` (включая ADO.NET) |
| **F#** | `coreclr`, `clr`, `vsdbg`, `dotnet` | файл помощника (1 запрос) | ✅ обязателен — тот же помощник, понимает option/union |
| **JavaScript / TypeScript** | `pwa-node`, `node`, `pwa-chrome`, `chrome`, `msedge`, `pwa-msedge`, `deno`, `bun` | preview адаптера (1–2 запроса) | встроен |

✅ = поставляется и используется автоматически

Типы колонок (`number`, `string`, `boolean`, `date`, `null`, `object`, …) определяются для каждого языка отдельно, поэтому сортировка и оси графиков ведут себя корректно везде.

| 🔀 **Сортировка** | Клик по заголовку; числа/даты/булевы сортируются по типу, текст — «естественно» (`2` раньше `10`), пустые ячейки всегда в конце |

Если идентификатор пришёл из другого файла, ссылка встаёт над объемлющим объявлением, а не громоздится на точке останова — точную строку и причину каждой ссылки показывает **Show Diagnostics** |
| 🧪 **Просмотр данных из кода** | Ссылка `Просмотр данных` над литералами коллекций: данные, прописанные в коде, открываются без запуска отладки — см. [ниже](#-без-точки-останова) |
| 🎯 **Локальные фильтры** | Воронка в каждом заголовке колонки открывает компактное всплывающее окно: поле значения, встроенный переключатель `/.*/ ` для регулярных выражений, режимы `include`/`exclude` и список известных значений; ссылка `Clear all filters` снимает все условия сразу |
| 🧠 **Фильтр по условию** | Кнопка `Фильтр строк по условию` рядом с поиском собирает условие из строк по колонкам и оставляет его чипом со снятием. Условие считается по захваченным строкам, не обращается к отладчику и применяется мгновенно |
| 🌳 **Панель значения** | Клик по `#` — весь элемент, клик по ячейке — только это поле; вложенные значения подгружаются из отладчика лениво |
| 📈 **Графики** | 9 типов диаграмм с настройками серий и экспортом в PNG |
| 💾 **Экспорт** | CSV, JSON, Excel (`.xlsx`) и XML — того самого отфильтрованного и отсортированного вида, который вы видите |
| 📌 **Снимки** | Закрепите снимок, чтобы изучать его после завершения сессии |
| 🌐 **Локализация** | Английский (основной) и русский — и манифест (`%key%`), и строки во время работы |
| 🧾 **Диагностика** | Какая стратегия использовалась, сколько запросов к адаптеру это стоило, почему быстрый путь не сработал, какие коллекции видны в текущем кадре, плюс заметки по каждому языку |

### 🔗 Локальные переменные в фильтре

Кнопка **Фильтр строк по условию** рядом с поиском собирает условие из строк по колонкам и оставляет его видимым чипом с кнопкой снятия. Условие считается локально, по захваченным строкам, поэтому применяется мгновенно и не занимает отладчик. Свободные идентификаторы, которые **не** являются колонками, вычисляются в текущем кадре — как параметр запроса:

```text
x.Day == dayOfMonth        ← dayOfMonth — локальная переменная остановленной строки
x.Price > budget * 1.2     ← budget тоже
```

## 💾 Экспорт

| Формат | Расширение | Примечания |
| --- | --- | --- |
| CSV | `.csv` | Кавычки по RFC 4180, BOM UTF-8 (чтобы Excel открывал корректно), настраиваемые разделитель/кавычки/перевод строки |
| JSON | `.json` | Типизированные значения (`null`, числа, булевы) и метаданные снимка вместо строк отображения |

Копирование в буфер обмена как TSV — команда `Exploring Collections: Copy Rows`.

Экспорт содержит **ровно те строки, которые вы видите** — с учётом фильтров, поиска и сортировки, — и расширение предупреждает, если коллекция была усечена, так что частичный экспорт не останется незамеченным.

## 🧰 Нативные помощники (встроены в расширение)

Именно помощники обеспечивают работу с ADO.NET коллекциями и богатыми типами в .NET. Они лежат в [`helpers/`](./helpers) — полный контракт в [helpers/README.md](./helpers/README.md).

| Язык | Помощник | Как включить |
| --- | --- | --- |
| C# / F# | `ExploringCollections.Helper.dll` | **Автоматически** — загружается в процесс через `Assembly.LoadFrom` при первом обращении |
| JavaScript / TypeScript | встроен | Ничего делать не нужно |

Все помощники говорят на одном маленьком конверте, поэтому расширению нужен один парсер на язык, а не на каждый тип:

```json
{ "__ec": 1, "kind": "sequence", "total": 14, "items": [ { "City": "Seoul" } ] }
```

`kind` — это `sequence`, `mapping` (элементы — пары `[key, value]`) или `record` (один объект). Ограничения, обнаружение циклов и глубину помощник обрабатывает сам, поэтому циклический граф даёт читаемую строку, а не зависший процесс. Помощник пишет страницу во временный файл, который расширение читает и удаляет: значение, возвращённое вызовом метода, адаптер обрезает примерно на 1 000 символах. Поэтому у коллекций .NET **один** путь: если помощник не загрузился или не смог записать файл, захват завершается понятной ошибкой, а не медленным обходом тысяч переменных. JavaScript/TypeScript помощник не нужен, и там обход переменных остаётся резервным путём.

| `exploringCollections.enableCharts` | `true` | Показывать вкладку графиков |

## 🏗️ Как это устроено

```text
      запрос на снимок
            │
            ▼
  ┌───────────────────────┐
  │ 1. быстрый путь       │   C#/F#: файл помощника (1 запрос, обязателен)
  │                       │   JS/TS: preview адаптера (1–2 запроса)
  │ 2. обход переменных   │   JS/TS: резервный путь, когда preview скрыт
  └───────────────────────┘
            │
            ▼  провайдеры языков (синтаксис, типы колонок)
  ┌───────────────────────┐
  │ снимок + модель строк │   неизменяемый, сериализуемый, экспортируемый
  └───────────────────────┘
            │
            ▼  webview со строгим CSP (без фреймворков и зависимостей)
  таблица · фильтры колонок · конструктор фильтра · 9 графиков · панель значения · экспорт
```

```text
src/            хост расширения: провайдеры, DAP-клиент, фильтры, экспорт, команды
webview/        интерфейс (чистый TypeScript, собственные SVG-графики)
helpers/        библиотеки-помощники с собственными наборами тестов
test/           модульные и интеграционные тесты (node:test поверх сборки)
resources/      иконка и графика для панели активности
docs/           скриншоты для README (попадают в VSIX, чтобы их показывал Marketplace)
scripts/        генерация иконки, генерация l10n, запуск тестов помощников
```

Осознанные решения: **никаких зависимостей времени выполнения** (свои писатели ZIP/XLSX, свои SVG-графики, свой парсер выражений), **строгий CSP** во webview, **неизменяемые снимки** (снимок можно перерисовать после завершения сессии) и **фильтр на базе AST**, чтобы условие никогда не переписывалось строковыми заменами.

```bash
npm run check            # проверка типов TypeScript 7
npm test                 # модульные тесты + наборы тестов всех помощников
npm run test:helpers     # только помощники (пропускает отсутствующие тулчейны)
npm run test:integration # запускает расширение в настоящем окне VS Code
npm run preview          # отрисовывает просмотрщик в media/screenshot-*.png
npm run package          # exploring-collections-1.0.0.vsix
```

Сборка помощников: `npm run package` кладёт в VSIX сборку .NET-помощника
(`helpers/dotnet/dist/ExploringCollections.Helper.dll` — одна сборка и для C#, и для F#). Она
хранится в git, поэтому свежий клон можно упаковать сразу; пересоберите её командой
`npm run build:helper:dotnet` после правок в `helpers/dotnet/`. Сериализатор
JavaScript/TypeScript внедряет само расширение, поэтому сборка для него не нужна.
`npm run test:helpers` прогоняет тесты .NET-помощника и пропускает запуск, если тулчейн не
установлен; команды сборки и тестов — в [helpers/README.md](./helpers/README.md).

`npm run test:integration` поднимает установленный Visual Studio Code с временным
профилем, запускает настоящую сессию отладки Node на примере программы и проверяет
CodeLens, ссылку в подсказке, конвейер захвата и панель — вплоть до снимков DOM через
безголовый рендерер (`npm run preview`).

Нужны Node.js 20+ (разработка велась на Node 26), TypeScript 7 и, для тестов .NET-помощника, .NET SDK.
