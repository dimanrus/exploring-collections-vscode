## ✨ Зачем это нужно

Отладчики в других IDE уже умеют показывать `List<T>`, `Dictionary<K,V>` или `DataTable` настоящей таблицей с данными, а не деревом. **Exploring Collections переносит этот опыт в Visual Studio Code — и идёт дальше, потому что не ограничивается .NET.**

Остановитесь на точке останова и смотрите на коллекцию как на *таблицу*, а не как на бесконечное дерево узлов.

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ 🔍 temperatures        ⌂ 14 из 14 строк · C# · coreclr                    │
│ 🔎 x.DegreeCelsius > 20                               📊 График  💾 Экспорт│
├────┬────┬───────────────┬──────────────────┬──────────┬───────────────────┤
│  # │ ▸  │ City          │ DegreeCelsius    │ Date     │ Feels             │
├────┼────┼───────────────┼──────────────────┼──────────┼───────────────────┤
│  2 │ ▸  │ Mexico City   │ 23               │ 2026-01-12│ warm             │
│  5 │ ▸  │ Houston       │ 26               │ 2026-01-09│ warm             │
│  8 │ ▸  │ Brisbane      │ 21               │ 2026-01-06│ warm             │
└────┴────┴───────────────┴──────────────────┴──────────┴───────────────────┘
```

## 🚀 Быстрый старт

1. Установите расширение из Marketplace (или нажмите `F5` в клоне этого репозитория).
2. Запустите отладку на **любом** поддерживаемом языке и остановитесь на точке останова.
3. В панели **Variables** щёлкните коллекцию **правой кнопкой** → **🔍 Explore collection**.
4. Либо вызовите команду **`Exploring Collections: Explore a Collection…`** из палитры команд и выберите любую переменную текущего кадра.

| Как открыть | Где |
| --- | --- |
| `🔍 Explore collection` **CodeLens** | **Над каждой коллекцией, доступной на точке останова** — по одной кликабельной ссылке на коллекцию, прямо в остановленном файле |
| `🔍 Explore collection` **ссылка в подсказке** | Наведите курсор на переменную-коллекцию в остановленном файле и щёлкните ссылку во всплывающей подсказке |
| `🔍 Explore collection` **контекстное меню** | Правая кнопка на переменной в **Variables**, **Watch** или **Call Stack** (`locals`) |
| `⌨️ Ctrl+Alt+E` / `⌘+Alt+E` | На любой поддерживаемой переменной во время отладки |
| `⌨️ Ctrl+Alt+Shift+E` | Выбор переменной из палитры команд с поиском |
| `🧭 Activity bar → Exploring Collections` | Каждая сессия отладки раскрывается в **список своих коллекций** (имя, количество элементов, тип); ниже — закреплённые и недавние снимки |
| `💡 Подсказка в строке` | На остановленной строке: `🔍 temperatures (14) · explore with Ctrl+Alt+E` |
| `🧪 Просмотр данных` | CodeLens над литералом коллекции в редакторе — **без запуска отладки** |

```text
    var temperatures = new List<Temperature>();     ▸ 🔍 Explore collection · temperatures · 14
    var lookup = new Dictionary<string, int>();     ▸ 🔍 Explore collection · lookup · 3
    Console.WriteLine(temperatures.Count);          ← остановились здесь
```

CodeLens появляются сразу при остановке, обновляются на каждом шаге и при смене кадра, и исчезают с завершением сессии. Каждая ссылка стоит на строке, где коллекция *появилась*, поэтому несколько коллекций из одного выражения не собираются в одну строку. Если идентификатора в этом файле нет (поле, параметр, сгенерированный член), ссылка привязывается к строке объемлющего объявления вместо точки останова, а команда **Show Diagnostics** показывает точную строку и причину выбора для каждой ссылки. Отключается настройкой `exploringCollections.showCodeLens`.

> **Важно** — в Visual Studio Code нет точки расширения для *hover в отладчике*: расширение не может добавить ссылку в ту строку подсказки, которую рисует адаптер отладки. Поэтому сделано два других пути: CodeLens над каждой коллекцией и собственный блок в подсказке (с работающей ссылкой `Explore collection`). Контекстные меню, подсказка в строке, дерево снимков и горячая клавиша завершают сценарий в рамках публичного API.

### 🧪 Без точки останова

Данные, **прописанные прямо в коде**, можно открыть без отладки. Поставьте курсор в файл с литералом коллекции и вызовите из палитры команд `Exploring Collections: Preview Collection Data from Source` — или просто нажмите CodeLens `🧪 Просмотр данных` над самим литералом:

```python
temperatures = [                                  # 🧪 Просмотр данных · temperatures · 3
    {"city": "Seoul", "degrees": 21},
    {"city": "Busan", "degrees": 24},
    {"city": "Incheon", "degrees": 22},
]
```

Разбор понимает синтаксис литералов всех поддерживаемых языков: массивы и объекты JavaScript/TypeScript, списки и словари Python (с комментариями и висящими запятыми), C# `new List<T> { new T { … } }` и `new Dictionary<K,V> { ["k"] = v }`, срезы Go и `map[string]T`, Rust `vec![Temperature { … }]`, списки записей F#, списки инициализации C/C++ и JSON-документы. После правки литерала нажмите `Ctrl+Alt+R`, чтобы перечитать данные.

## 🌍 Поддерживаемые языки

Девять языков, три стратегии получения данных. **Универсальный обход переменных** работает с любым адаптером, поэтому коллекция доступна всегда; **быстрые пути для конкретных языков** делают это точнее и быстрее.

| Язык | Адаптеры | Быстрый путь | Нативный помощник | Проталкивание фильтра |
| --- | --- | --- | --- | --- |
| **C#** | `coreclr`, `clr`, `vsdbg`, `dotnet` | `System.Text.Json` / `Newtonsoft.Json` | ✅ `ExploringCollections.Helper.dll` (включая ADO.NET) | ✅ LINQ (`.Where`) |
| **F#** | `coreclr`, `clr`, `vsdbg`, `dotnet` | `System.Text.Json` / `Newtonsoft.Json` | ✅ тот же помощник, понимает option/union | ✅ `Seq.filter` |
| **JavaScript / TypeScript** | `pwa-node`, `node`, `pwa-chrome`, `chrome`, `msedge`, `pwa-msedge`, `deno`, `bun` | сериализатор внутри процесса | встроен | ✅ `Array.filter` |
| **Python** | `debugpy`, `python` | `json.dumps` | ✅ `exploring_collections_helper.py` | ✅ списковое включение |
| **Go** | `go`, `delve` | `json.Marshal` | ✳️ необязательный пакет | ➖ на клиенте |
| **Rust** | `lldb`, `rust-gdb`, `gdb`, `cppdbg`, `code-lldb` | разбор `{:?}` | ✳️ необязательный модуль | ➖ на клиенте |
| **C++ / C** | `cppdbg`, `cppvsdbg`, `lldb`, `codelldb`, `gdb` | — | ✳️ необязательный заголовок | ➖ на клиенте |

✅ = поставляется и используется автоматически · ✳️ = поставляется, нужно подключить в своей программе · ➖ = фильтрация на клиенте

Типы колонок (`number`, `string`, `boolean`, `date`, `null`, `object`, …) определяются для каждого языка отдельно, поэтому сортировка и оси графиков ведут себя корректно везде.

### 🔗 Локальные переменные в фильтре

Кнопка **Фильтр по всей коллекции** рядом с поиском собирает условие из строк по колонкам, проталкивает его в отлаживаемый процесс, когда перевод точный, и оставляет видимым чипом с кнопкой снятия. Свободные идентификаторы, которые **не** являются колонками, вычисляются в текущем кадре — как параметр запроса:

```text
x.Day == dayOfMonth        ← dayOfMonth — локальная переменная остановленной строки
x.Price > budget * 1.2     ← budget тоже
```

## 🧠 Язык фильтров

Единый синтаксис, подстраиваемый под каждый язык. Префиксы `x =>`, `(x) =>` и F# `fun x ->` необязательны.

```text
x.DegreeCelsius > 20 && x.Feels == "warm"
(entry) => entry["Key"].StartsWith("A") || entry.Value > 100
fun x -> x.Age >= minAge and not (x.Country = "N/A")
WHERE len(x.Tags) in (2, 3) and like(x.Name, "S%")
```

| Группа | Поддерживается |
| --- | --- |
| Сравнение | `==` `!=` `<>` `>` `>=` `<` `<=` `=` (равенство, в зависимости от диалекта языка) |
| Логика | `&&` `\|\|` `!` `and` `or` `not` |
| Принадлежность | `in`, `not in`, литералы `(a, b, c)` и `[a, b, c]` |
| Шаблон | `like(text, "S%")` — есть и вариант-метод |
| Функции | `len`/`length`/`count`, `lower`/`upper`, `trim`, `abs`, `round`, `floor`, `ceil`, `sqrt`, `pow`, `min`, `max`, `sum`, `avg`, `contains`, `startswith`, `endswith`, `indexof`, `matches`, `substring`, `replace`, `concat`, проверки на пустоту (`isnull`, `isempty`, `isnotnull`), приведения (`int`, `float`, `string`, `bool`) и части даты (`year`, `month`, `day`, `dayofweek`, `hour`, `minute`, `second`, `now`, `today`) |
| Доступ | `x.City`, `x.Address.City`, `x["Key"]`, `x[0]`, `x.Items.Count` |

**Политика проталкивания** — фильтр **всегда** вычисляется локально, чтобы поведение было одинаковым во всех языках. Дополнительно он отправляется в отлаживаемый процесс только когда:

1. коллекция больше загруженного окна, **и**
2. провайдер может перевести выражение **точно** (строковые литералы никогда не переписываются текстовыми заменами).

Если условие не выполнено, вы получите предупреждение с объяснением, а загруженные строки будут отфильтрованы на клиенте.

## 💾 Экспорт

| Формат | Расширение | Примечания |
| --- | --- | --- |
| CSV | `.csv` | Кавычки по RFC 4180, BOM UTF-8 (чтобы Excel открывал корректно), настраиваемые разделитель/кавычки/перевод строки |

## 🧰 Нативные помощники (необязательно, по языкам)

Именно помощники обеспечивают работу с ADO.NET коллекциями и богатыми типами в .NET. Они лежат в [`helpers/`](./helpers) — полный контракт в [helpers/README.md](./helpers/README.md).

| Язык | Помощник | Как включить |
| --- | --- | --- |
| C# / F# | `ExploringCollections.Helper.dll` | **Автоматически** — загружается в процесс через `Assembly.LoadFrom` при первом обращении (отключается настройкой `exploringCollections.enableLanguageHelpers`) |
| Python | `exploring_collections_helper.py` | **Автоматически** — выполняется в отлаживаемом процессе и переиспользуется |
| JavaScript / TypeScript | встроен | Ничего делать не нужно |
| Go | `exploring_collections.go` | Импортируйте пакет и вызовите `exploringcollections.Dump(x)` |
| Rust | `exploring_collections.rs` | Подключите модуль и вызовите `exploring_collections::dump_json(&x)` |
| C / C++ | `exploring_collections.h` | Скомпилируйте и вызовите `exploring_collections::dump_json_cstr(x)` (C++ макрос `EC_OBJECT`) или C API дескрипторов |

Все помощники говорят на одном маленьком конверте, поэтому расширению нужен один парсер на язык, а не на каждый тип:

```json
{ "__ec": 1, "kind": "sequence", "total": 14, "items": [ { "City": "Seoul" } ] }
```

`kind` — это `sequence`, `mapping` (элементы — пары `[key, value]`) или `record` (один объект). Ограничения, обнаружение циклов и глубину помощник обрабатывает сам, поэтому циклический граф даёт читаемую строку, а не зависший процесс. **Ни один помощник не обязателен** — обход переменных всегда доступен как резервный путь.

| `exploringCollections.dictionariesAsRows` | `true` | Словари как строки «ключ/значение», а не одной широкой строкой |
| `exploringCollections.customDebugTypes` | `{}` | Дополнительные идентификаторы типов отладки, например `{ "my-runtime": "csharp" }` |
| `exploringCollections.excludedMembers` | `["Capacity","Count","Length","LongLength","_count","__len__"]` | Члены, которые никогда не становятся колонками |

## ⚠️ Ограничения (честный список)

- **Нет точки расширения для hover в отладчике.** VS Code не позволяет расширению вставить ссылку в ту строку подсказки, которую формирует сам адаптер отладки. До просмотрщика ведут CodeLens над коллекцией, наш дополнительный блок в подсказке, контекстные меню, подсказка в строке и горячая клавиша, но *единая* ссылка в одной подсказке публичным API недостижима. *(Ограничение API, а не пропущенная функция.)*
- **Захват ограничен по времени.** `exploringCollections.captureBudgetMs` (30 с) ограничивает чтение коллекции из отладчика (по дереву переменных нужен один запрос на элемент); прочитанные к этому моменту строки показываются с пометкой об усечении, а прогресс виден в уведомлении. Массовые пути (помощник, страницы вычислителя) не затронуты.
- **Окно переменных ограничено.** Если `maxRows` меньше коллекции, материализуется только её часть; об этом сообщается, а добраться до остального позволяет проталкивание фильтра. Обход теперь идёт по страницам адаптера, поэтому собственный размер страницы адаптера больше не обрезает окно — а если адаптер вообще не умеет страницы, в статус-баре видно, сколько элементов он всё-таки отдал.
- **Помощник для Rust разбирает вывод `Debug`.** Циклические значения зациклятся внутри `format!` раньше, чем расширение сможет вмешаться, — для графов используйте `dump_json`.
- **Для C нужен API дескрипторов.** Шаблонный API C++ недоступен из C, поэтому для структур применяются таблицы `ec_field_descriptor`.
- **Только Python 3.** Помощник использует f-строки и `dataclasses`.
- **Для Go нужна поддержка `call` в Delve.** Быстрые пути на основе вычисления выражений требуют версии Delve, умеющей вызывать функции в целевом процессе; иначе используется обход переменных.
- **Проталкивание фильтра доступно только для C#/F#/JavaScript/TypeScript/Python.** В остальных языках фильтруется локальное окно.
- **Просмотр из кода читает исходный текст.** Литералы, значения которых вычисляются (`Load()`, `items[0]`, переменная), показываются пустыми ячейками со счётчиком в предупреждении — просмотр предназначен для данных, полностью записанных в коде.

## 🏗️ Как это устроено

```text
      запрос на снимок
            │
            ▼
  ┌───────────────────────┐   код в отлаживаемом процессе не обязателен
  │ 1. нативный помощник  │   C#/F#, Python, ✳️ Go/Rust/C/C++
  │ 2. вызов сериализатора│   System.Text.Json, json.dumps, json.Marshal, {:?}
  │ 3. обход переменных   │   универсальный резервный путь через DAP
  └───────────────────────┘
            │
            ▼  провайдеры языков (синтаксис, типы, диалекты фильтров)
  ┌───────────────────────┐
  │ снимок + модель строк │   неизменяемый, сериализуемый, экспортируемый
  └───────────────────────┘
            │
            ▼  webview со строгим CSP (без фреймворков и зависимостей)
  таблица · фильтры колонок · строка LINQ · 9 графиков · панель значения · экспорт
```

```text
src/            хост расширения: провайдеры, DAP-клиент, фильтры, экспорт, команды
webview/        интерфейс (чистый TypeScript, собственные SVG-графики)
helpers/        библиотеки-помощники с собственными наборами тестов
test/           модульные и интеграционные тесты (node:test поверх сборки)
resources/      иконка и графика для панели активности
scripts/        генерация иконки, генерация l10n, запуск тестов помощников
```

Осознанные решения: **никаких зависимостей времени выполнения** (свои писатели ZIP/XLSX, свои SVG-графики, свой парсер выражений), **строгий CSP** во webview, **неизменяемые снимки** (снимок можно перерисовать после завершения сессии) и **фильтр на базе AST**, чтобы условие никогда не переписывалось строковыми заменами.

## 🛠️ Сборка из исходников

```bash
npm install
npm run build            # dist/extension.js + dist/webview.js
npm run check            # проверка типов TypeScript 7
npm test                 # модульные тесты + наборы тестов всех помощников
npm run test:helpers     # только помощники (пропускает отсутствующие тулчейны)
npm run test:integration # запускает расширение в настоящем окне VS Code
npm run preview          # отрисовывает просмотрщик в media/screenshot-*.png
npm run package          # exploring-collections-1.0.0.vsix
```

Сборка помощников: `npm run package` кладёт в VSIX сборку .NET-помощника
(`helpers/dotnet/dist/ExploringCollections.Helper.dll` — одна сборка и для C#, и для F#). Она
хранится в git, поэтому свежий клон можно упаковать сразу; пересоберите её командой
`npm run build:helper:dotnet` после правок в `helpers/dotnet/`. Остальным помощникам сборка не
нужна: Python, Go, Rust и C/C++
поставляются исходниками, которые отлаживаемый процесс компилирует или подключает сам, а
сериализатор JavaScript/TypeScript внедряет расширение. У каждого помощника свой набор тестов
(`npm run test:helpers` прогоняет все, отсутствующие тулчейны пропускает); команды сборки, запуска
и тестов по языкам — в [helpers/README.md](./helpers/README.md).

`npm run test:integration` поднимает установленный Visual Studio Code с временным
профилем, запускает настоящую сессию отладки Node на примере программы и проверяет
CodeLens, ссылку в подсказке, конвейер захвата и панель — вплоть до снимков DOM через
безголовый рендерер (`npm run preview`).

Нужны Node.js 20+ (разработка велась на Node 26), TypeScript 7 и, для наборов тестов помощников, те тулчейны, что у вас установлены (`.NET 10`, Python 3, Go, Cargo, `g++`/`gcc`).
