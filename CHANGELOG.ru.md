## 🚀 [1.1.0] — 2026-10-19

[🇬🇧 English version](./CHANGELOG.md#en-1-1-0)

### ✨ Добавлено

- **Предпросмотр данных без отладки** — данные, зашитые в исходник, можно открыть без сессии отладки: CodeLens `Preview data` над литералом, команда `Preview Collection Data from Source` и пункт контекстного меню редактора. Разбираются литералы C#, F#, JavaScript/TypeScript и JSON; `Ctrl+Alt+R` перечитывает литерал после правки.
- **Конструктор условия** — кнопка рядом с поиском собирает условия `WHERE x => …` по столбцам (содержит, не содержит, равно, не равно, начинается с, заканчивается на, регулярное выражение, больше/меньше/между, null/пусто/true/false) с живым предпросмотром и разбором уже заданных условий. Условие считается по захваченным строкам и не требует запроса к отладчику.
- **Кнопка «На всю ширину» в заголовке редактора** — слева от *Split Editor Right* вместо кнопки внутри панели.
- **Раздел «Explore code lens» в отчёте диагностики** — строка каждого CodeLens, причина выбора этой строки, состояние `editor.codeLens` и обеих настроек.
- **Пункт «All (N)» в постраничном выводе** — таблица может показать все строки сразу.
- **Отдельный чип на каждое условие** — панель фильтра показывает каждое условие активного фильтра отдельно, у каждого чипа свой ✕, который убирает только это условие; диапазон остаётся одним чипом.
- **CodeLens «Explore collection»** — над каждой доступной в текущем кадре коллекцией прямо в остановленном файле: имя, количество элементов, один клик до просмотрщика. Обновляется на каждом шаге и при смене кадра.
- **Ссылка Explore во всплывающей подсказке** — наведение на переменную-коллекцию добавляет собственный блок подсказки со ссылкой `Explore collection` (команда разрешена через `isTrusted` только для этой команды).
- **Коллекции в дереве** — узел сессии отладки раскрывается в список коллекций кадра (имя, количество элементов, тип) с командой Explore; раньше там был только список сессий.
- **Новые настройки** `exploringCollections.showCodeLens` и `exploringCollections.showHoverLinks`.

### 🔧 Изменено

- **Один быстрый путь; запасной — только у JavaScript/TypeScript.** Движок захвата больше не перебирает цепочку независимых стратегий. Провайдер языка даёт одно быстрое чтение: предпросмотры адаптера для JavaScript/TypeScript и файл помощника для C#/F#. Объявленный размер читается из `Count = N`, даже если адаптер сообщает ещё и счётчики членов, поэтому `List<T>` из 1000 элементов распознаётся как 1000.
- **Медленный обход .NET убран.** Коллекции C#/F# читаются только через помощник: один запрос на страницу вместо запроса на элемент, поэтому 1000 строк занимают около 300 мс вместо 27 секунд и ничего не обрезается молча. Если помощник не загружается или не может прочитать свой файл, захват завершается с понятным уведомлением, а не переходит к обходу. Выражения сериализатора .NET и вся машинерия диапазонов и чанков, существовавшая только для этого запасного пути, удалены.
- **Обход переменных остался для JavaScript/TypeScript.** Он используется, когда адаптер скрывает предпросмотры элементов; `exploringCollections.captureBudgetMs` теперь ограничивает только его.
- **Ссылка Explore ставится над объявлением коллекции.** Определяется строка, где коллекция объявлена или присвоена (`var x = …`, `x := …`, `let x: T = …`, параметр метода), и только если такой строки в файле нет — первое упоминание или строка останова.
- **Компактные фильтры колонок.** Поле значения и переключатель регулярного выражения стоят в одной строке, поля и отступы уменьшены, само окно фильтра уже (248 px вместо 300 px).
- **Один выпадающий список для оси Y.** Многострочный список столбцов убран: несколько серий получаются выбором колонки группировки.
- **Раскладка просмотрщика подстраивается.** Панель деталей скрывается кнопкой (или крестиком в её заголовке), таблицу можно свернуть кнопкой, а разделители меняют высоту графика и ширину панели деталей; кнопка в правом верхнем углу разворачивает вкладку на всю ширину редактора.
- **Панель деталей строки перерисована.** Имя, тип и значение выровнены по колонкам, вложенность показана направляющими, выбранная ячейка подсвечивается, у каждого значения есть кнопка копирования при наведении, в заголовке — метка строки, тип, счётчик полей и действия.
- **Кнопка «На всю ширину» больше не дублируется.** Для развёрнутой группы VS Code рисует собственную кнопку восстановления в той же группе `navigation`, поэтому наша скрывается по тому же контекстному ключу, что использует сам VS Code (`!editorPartMaximizedEditorGroup`); встроенная кнопка по-прежнему восстанавливает группу.
- **Локальные фильтры доступны всегда.** Кнопка `Local filter` убрана: воронка с самого начала стоит в заголовке каждой колонки, а `Clear all filters` над таблицей по-прежнему снимает все условия сразу.
- **Скриншоты README перерисованы** (`npm run preview`), добавлен вид локального фильтра.

### 🗑 Удалено

- **Поддержка Python, Go, Rust, C и C++ удалена.** Расширение сосредоточено на JavaScript/TypeScript, C# и F#: провайдеры, их помощники (`helpers/python`, `helpers/go`, `helpers/rust`, `helpers/cc`), диалект фильтра Python, разбор литералов для этих языков, подсказки и тесты удалены. `customDebugTypes` по-прежнему сопоставляет пользовательский тип отладки одному из поддерживаемых провайдеров (`csharp`, `fsharp`, `javascript`).
- **Ручной ввод условия `WHERE x => …`.** Команда `Exploring Collections: Set Filter…` с полем ввода удалена: условия собираются кнопкой **Filter the whole collection** рядом с поиском, а префикс `WHERE` по-прежнему понимается при чтении сохранённых условий.

### 🐞 Исправлено

- **Просмотрщик больше не остаётся на экране загрузки.** Заглушка `Loading collection…` очищала корневой элемент webview и уносила за собой всю построенную обвязку (панель инструментов, строку фильтра, таблицу, панель значения, уведомления), поэтому данные, приходившие от хоста, рендерились в отсоединённые узлы и пользователь видел только спиннер. Заглушка теперь живёт внутри области таблицы и снимается при первом снимке.
- Текст заглушки локализован (английский/русский) вместо жёстко зашитой строки.
- **Файл остановки теперь определяется всегда.** `DebugStackFrame` в VS Code не сообщает ни файл, ни строку кадра, поэтому источник кадра запрашивается у адаптера (`stackTrace`) и кэшируется. Без этого CodeLens и hover не находили остановленный файл, и подсказки не показывались.
- **Распознавание коллекций больше не зависит от счётчиков адаптера.** Некоторые адаптеры (например js-debug) не присылают `indexedVariables`/`namedVariables`, а описывают значение как `(12) [{…}]`. Теперь коллекция определяется и по такому описанию, поэтому JavaScript/TypeScript получили полноценные CodeLens, hover и список в дереве.
- Ссылка CodeLens ставится на строку, где коллекция появилась, поэтому несколько коллекций из одного выражения больше не собираются в одну строку.
- **Include/Exclude в локальном фильтре** — переключатель снова взаимоисключающий (у радиокнопок не было общей группы, поэтому вторым нажатием нельзя было отменить первое).
- **Селектор количества строк** — селектор внизу больше не сохраняет предыдущее значение.
- **Выбор столбца для графика** — громоздкий список убран, выпадающий список остался.
- **Окно переменных больше не обрезается до первой страницы.** Перечисление `variables` теперь проходит страницы до `maxRows`, поэтому адаптер с собственным размером страницы (или игнорирующий `count`) отдаёт всё окно вместо первых 25 элементов; если адаптер повторяет одну и ту же страницу (игнорирует `start`), обход останавливается и сообщает об этом, а не зацикливается.
- **Размер берётся из текста предпросмотра, когда адаптер не сообщает счётчики.** `vsdbg` не присылает `indexedVariables` для `List<T>`: размер виден только в предпросмотре (`Count = 50000`). Теперь это число используется как объявленный размер, поэтому обрезанное адаптером окно видно и дочитывается постранично, а не молча остаётся на 25 строках.
- **Захват больше не может зависнуть.** Бюджет `exploringCollections.captureBudgetMs` (30 с по умолчанию) ограничивает обход переменных (один запрос на элемент, поэтому 10 000 строк раньше читались минутами). Прочитанное к этому моменту показывается как обрезанное окно с предупреждением, а уведомление сообщает прогресс («1 234 из 10 000 строк»).
- **Средние коллекции читаются одним вызовом помощника.** `List<Employee>` из 1000 элементов раньше читался поэлементно и возвращался обрезанным на 962 строках; теперь быстрый путь C#/F# сериализует всю страницу через помощник во временный файл и читает её с диска.
- **Неудачное вычисление больше не выглядит значением.** vsdbg отвечает на неудачный `evaluate` успешным ответом, где в значении лежит исключение, а признак отказа — только в presentation hint; теперь клиент считает это ошибкой, и при отсутствующей сборке помощника видно «helper load failed: … FileNotFoundException», а не запутанную следующую ошибку.
- **Отсутствующий помощник сообщает о себе, а не гадает.** Когда помощник не загружается, не может записать файл или расширение не может его прочитать (например, удалённая цель), захват сообщает причину и останавливается; молчаливого обхода и наполовину прочитанной коллекции нет.
- **Фильтры больше не выполняются внутри отлаживаемой программы.** Когда коллекция была больше загруженного окна, условие отправлялось в отладчик как нативное выражение. Оно возвращало сразу весь отфильтрованный набор, а адаптер обрезает результат примерно на 1 000 символах, поэтому ответ никогда не разбирался; а `System.Text.Json`, которым это сериализовалось для C#/F#, вообще не подключён в вычислителе выражений (`error CS0234`), так что C#/F# тоже не могли фильтровать за пределами окна. При этом каждая попытка стоила запроса к отладчику и оставляла предупреждение. Теперь условие считается только по захваченным строкам: применение занимает миллисекунды, не требует запросов и не может занять отладчик, а если коллекция была обрезана по окну, результат честно сообщает, сколько строк прочитано.
- **У конструктора условия нет режима OR.** `Match all` / `Match any` убраны: условия всегда соединяются через `&&`, поэтому один фильтр применяется ко всем захваченным строкам, без переключения между связками. Уже заданное условие с `||` не меняется, пока его не отредактируют.
- **Снятие фильтра мгновенное.** Крестик на чипе фильтра заново запрашивал у хоста всю нефильтрованную коллекцию (12–118 МБ) и перерисовывал вид дважды. Теперь просмотрщик держит захваченные строки рядом с отфильтрованными, поэтому снятие условия происходит локально: одна отрисовка, без передачи данных.
- **Одна отрисовка — один проход по строкам.** Таблица, строка состояния и график по отдельности прогоняли весь конвейер вида (сортировку, поиск, фильтры колонок) по всем захваченным строкам, поэтому одно нажатие клавиши в поиске стоило трёх проходов — примерно по 200 мс на 100 000 строк. Теперь конвейер считается один раз на отрисовку и переиспользуется.
- **Применение фильтра больше не отправляет строки дважды.** Сообщение `filterResult` несло весь снимок *и* отфильтрованные строки, то есть две копии всех данных: 23 МБ на 10 000 строк, 118 МБ на 50 000 и 236 МБ на 100 000, и всё это структурированно копировалось в webview при каждом применении. Теперь строки передаются один раз, а webview не держит вторую копию — именно это и подвешивало отфильтрованный вид большой коллекции.
- **Конструктор фильтра больше не показывает мёртвое поле «Enter a value».** Это серое поле было предпросмотром сгенерированного выражения и рисовалось пустым, пока условие не собрано; теперь оно появляется только когда есть что показать, и в окне нет недоступного элемента управления.
- **Ответ, обрезанный адаптером, больше не принимается за маленькую коллекцию.** Такие адаптеры, как js-debug, вырезают середину длинного результата `evaluate` символом `…`, и этот текст всё ещё разбирается как JSON — с искажёнными членами и пропущенными строками. Теперь такая страница распознаётся и запрашивается меньшими кусками, а размер страницы сходится к тому, который адаптер отдаёт целиком.
- **Большие коллекции читаются целиком.** Строки JavaScript/TypeScript строятся из предпросмотров адаптера за один-два запроса; страницы C#/F# сериализуются помощником во временный файл за один запрос, поэтому длина строки `evaluate` больше не ограничивает захват.
- **Обрезанное окно теперь видно.** `Truncated` больше не зависит только от `maxRows`: когда адаптер отдаёт меньше, чем объявил, строка состояния показывает `Truncated: N total`, а предупреждения называют числа.
- **JavaScript-сериализатор был синтаксически сломан.** Список операторов соединялся через `;`, поэтому точка с запятой между `if (…) { … }` и `else if` делала выражение синтаксической ошибкой в отлаживаемом процессе (`Uncaught SyntaxError: Unexpected token 'else'`). Из-за этого быстрый путь JavaScript/TypeScript никогда не запускался и коллекции читались обходом: 20 000 элементов занимали 169 секунд. Теперь это один оператор, и быстрый путь работает.

### 🧪 Тесты

- Новый набор `test/webviewBoot.test.ts` загружает **реальный собранный webview** в DOM: проверяет рукопожатие `ready`, отрисовку строк, фильтр, уведомления и отсутствие вечного спиннера. Именно он поймал описанный выше баг.
- Набор `test/frameFeatures.test.ts` покрывает CodeLens, размещение ссылки по строкам, hover-ссылки и кэш поиска коллекций.
- **Интеграционный набор в настоящем VS Code** (`npm run test:integration`) запускает реальную сессию отладки Node и проверяет CodeLens в редакторе, ссылку в подсказке, открытие панели по клику, захват коллекции из контекстного меню, команды снимка и захват коллекции из 50 000 элементов — 11 проверок.
- `npm run preview` рендерит настоящий webview в PNG через безголовый Chromium: эти изображения попали в README (таблица, детали строки, локальный фильтр, график).
- Тесты геометрии раскладки: границы высоты графика и ширины панели деталей, включая вырожденные и NaN значения.
